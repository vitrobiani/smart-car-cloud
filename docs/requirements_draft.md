## 1. רקע

Volkswagen מזמינה קבוצות סטודנטים לבנות פרוטוטייפ ענן של "מוח רכב" (Car Brain) בהשראת Herbie – רכב שהוא בן-לוויה אישי, אקטיבי וידידותי.

**הבעיה:** הרכב היום פסיבי. הוא מבצע תגובות פשוטות (בלימה, ביפ), וההתראות שלו מרגיזות ומסיחות דעת ("Nanny behavior"). הוא לא יודע להפעיל שיקול דעת בהתאם להקשר או לזהות הנהג.

**החזון:** רכב שמלווה, מדריך ומגיב לנהג בצורה חברתית ואקטיבית, בהתאמה לפרסונת הנהג ולהקשר הנהיגה.

**ארבע פרסונות הנהג:**
1. **נהג חדש** – מורה ומלווה, הגבלת כוח, עידוד, אישור הורה/בעלים לחריגות.
2. **נהג ותיק** – ניטור הסחות דעת, שיחות בדיקת ערנות, ניטור סביבה עדין.
3. **נהג ספורטיבי (geofenced)** – מדריך מירוצים, שחרור הדרגתי של יכולות ADAS.
4. **נהג אקולוגי** – אופטימיזציה אנרגטית, הדרכת נהיגה חסכונית.

## 2. מטרות שלב 2

- להראות **התנהגות מערכת אמיתית** – עיבוד נתונים, לוגיקת החלטה, אינטראקציה, פלט אמיתי.

## 4. משוב Volkswagen ותשובות

| נקודה | משוב VW | תשובה שלנו |
|-------|---------|-------------|
| Proactivity Triggers | איך מפעילים לוגיקה פרואקטיבית? | הפרדה בין **פונקציות דגימה (chronic)** לבין **פונקציות אירועים (event-driven)**, מעל שכבת orchestrator שמחליטה מתי לדבר. |
| AI Architecture | מודל יחיד או ריבוי סוכנים? | **מערכת מתוזמרת:** חוקים דטרמיניסטיים (זולים ומהירים) על ה-hot path; LLM רק לשפה, חינוך, וסיכומים. |
| Edge vs Cloud | מה רץ איפה? | ייכתב מסמך יעודי; כלל אצבע: latency-critical + private → edge; heavy reasoning + storage → cloud. |
| Generic Architecture | להשאיר מקום להרחבה | Context model גנרי (user/vehicle/env/interaction), פרסונות ורכיבים כ-plugins. |

## 5. משימות

### 5.1 תשתית ענן וארכיטקטורה
- [ ] בחירת stack: שפה, framework, DB, message bus, LLM provider.
  - המלצה: **Python + FastAPI + PostgreSQL + Redis + Docker Compose + Anthropic/OpenAI API**.
- [ ] יצירת monorepo/multi-repo skeleton.
- [ ] `docker-compose.yml` עם כל השירותים.
- [ ] קונפיגורציה סביבתית (`.env`, secrets).
- [ ] Observability בסיסי: לוגים מבוזרים + trace-id לכל אירוע.
- [ ] מסמך ארכיטקטורה + תרשים רכיבים.
- [ ] מסמך חלוקת Edge vs Cloud (חובה למשוב VW).
- [ ] מסמך Extensibility – איך מוסיפים פרסונה חדשה או מקור הקשר חדש.

### 5.2 מסד נתונים
- [ ] סכימה של **פרופיל נהג** (זהות, פרסונה, העדפות, שירים אהובים, אנשי קשר לחירום).
- [ ] סכימת **טלמטריה גולמית** (event store לזמן ריצה + agregated לניתוח).
- [ ] סכימת **מסלולים / מקומות קבועים** (בית, עבודה, גיאופנסים ספורט, אזורי בעיה בעבר).
- [ ] סכימת **היסטוריית נסיעות** (סיכומים לכל נסיעה).
- [ ] סכימת **event log** (בלימות חדות, חריגות מהירות, התראות שיצאו + תגובת הנהג).
- [ ] סכימת **coaching history** (מה נאמר, מתי, איך הנהג הגיב – ל-narrative של למידה).
- [ ] סכימת **התקדמות פרסונה** (רמת מיומנות של נהג ספורטיבי, ציון אקולוגי מצטבר וכו').
- [ ] Migrations / seed data.

### 5.3 רשימת חיישנים (Sensor Inventory)

> להשלים לפי הטבלה ב-`docs/aaos_inputs_test_template.csv.xlsx`.

**מהרכב (VHAL – מדומה בשלב 2):**
- Speed, wheel speeds, steering angle (גלגל, לא הגה), gear (selected/engaged), brake %, accelerator %, fuel/battery level, range, odometer, ignition, turn signals, wipers, headlights, parking brake, seatbelt, door status, tire pressure, cabin/outside temp.

**חיישני מכשיר / AAOS:**
- GPS (lat/lon/altitude/bearing/speed), accelerometer, linear acceleration, gyroscope, rotation vector, light sensor.

**נהג-פייסינג (מדומה בשלב 2):**
- מצלמת פנים (רגשות, מבט, מצב עיניים), מצלמת ידיים על ההגה, לחץ אחיזה, דופק (הגה/wearable), מיקרופון (קול + רעש רקע).

**חוץ-פייסינג:**
- מצלמות 360°, radar/ultrasonic, ADAS objects.

**זיהוי:**
- Bluetooth (beacon/MAC), פרופיל מאוחסן.

**הקשר חיצוני (API, לא חיישן – אבל באותו layer):**
- Weather, road-type/geocoding, speed limits, geofences.

### 5.4 פונקציות קלט – דגימה (Chronic / Periodic)

פונקציות שרצות באינטרוול קבוע ומעדכנות את שכבת ההקשר.

- [ ] **בדיקות מהירות** (מול מגבלת דרך).
- [ ] **בדיקת ערנות** (rolling window על אותות פנים/דופק/היגוי).
- [ ] **איכות אחיזה בהגה** (יציבות, לחץ, זמן ידיים על ההגה).
- [ ] **שמירת מרחק** מהרכב שלפנים.
- [ ] **מהירות מול מגבלה פוסטית לדרך.**
- [ ] **רמת דלק/סוללה + טווח משוער.**
- [ ] **רמת הסחת דעת** (נוסעים, שימוש בטלפון, רעש רקע).
- [ ] **מגמת עייפות** (חלון זמן, לא רק snapshot).
- [ ] **ציון אקולוגי** (חלקות תאוצה, בזבוז בבלימה).
- [ ] **טמפרטורה פנימית/חיצונית** (המלצות נוחות, HVAC).
- [ ] **מיקום מול בית/עבודה/מקומות מוכרים.**

### 5.5 פונקציות קלט – מבוססות אירועים (Event-Driven)

פונקציות שנורות כתגובה לשינוי מצב.

- [ ] **שחרור ההגה.**
- [ ] **בלימה חדה.**
- [ ] **תאוצה חדה (mirror של בלימה).**
- [ ] **מעבר נתיב** (עם/בלי איתות).
- [ ] **זיהוי מכשולים** (חורים, הולכי רגל, חיות).
- [ ] **חציית סף מהירות** (למשל >120 קמ"ש).
- [ ] **כניסה/יציאה מ-geofence** (אזור ספורט, בית ספר, בית חולים, בית).
- [ ] **תחילת נסיעה / סיום נסיעה.**
- [ ] **זיהוי נהג / כניסת נוסע** (Bluetooth event).
- [ ] **צניחה ברמת ערנות** מתחת לסף.
- [ ] **שינוי מזג אוויר** (התחלת גשם, ראות נמוכה).
- [ ] **דלק/סוללה מתחת לסף.**
- [ ] **התקרבות ל"נקודה חמה"** (אירוע קודם באותו מקום).
- [ ] **בקשת/מענה אישור הורה/בעלים** (flow חריגה לנהג חדש).
- [ ] **כשל LLM API / ניתוק ענן** → מעבר למצב degraded.

### 5.6 פונקציות עיבוד ופרופיל

- [ ] **חישוב פרופיל נהג מצטבר:**

- [ ] **עדכון התקדמות פרסונה** (העלאת רמת נהג ספורטיבי כשמשתפר).

### 5.7 המוח – Orchestrator / Decision Engine

הרכיב שמחליט **האם ומה** לומר, על סמך כל האותות.

- [ ] מנוע חוקים דטרמיניסטי לתגובות מיידיות.
- [ ] מדיניות פרסונה – בחירת חוקים ופרומפטים בהתאם.
- [ ] **Non-nanny throttle** – מגביל תדירות התראות, prioritization, cooldowns.
- [ ] Routing – מתי לפנות ל-LLM ומתי לחוקים בלבד.
- [ ] מצב degraded – מה עושים כשה-LLM לא זמין.

### 5.8 שכבת פלט (Delivery Layer)
- [ ] אבסטרקציה של ערוץ התראה (TTS-string, dashboard event, chat message).
- [ ] ניהול קדימויות ומחסום (למניעת התנגשות בין הודעות).
- [ ] תמיכה בהודעה סינכרונית ואסינכרונית.
- [ ] תמיכה בבקשות אישור מהמשתמש (אישור הורה, אישור חריגה).
